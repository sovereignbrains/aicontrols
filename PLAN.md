# AIControls — план

**Решено 17.10.2026: C++23 (вариант A).**

## Что нужно от клиента (по факту 2 месяцев использования)

Используется: чат с Claude и секреты. Всё остальное в старом SSH Client (терминал, SFTP,
пробросы, «Инструменты», сейф с мастер-паролем, Hello, Google Диск) — не нужно.

Обязательно перенести:
1. Чат: стриминг ответа, markdown, код с подсветкой, выделение и копирование текста.
2. Список чатов, продолжение старого разговора (resume), выбор модели, «Стоп».
3. Сообщение, пока Claude работает, уходит в текущий ход (коммит 4662af2 в старом репо, не запушен).
4. Подтверждение каждой команды/записи файла — карточкой в чате.
5. Мои инструменты: run_command, read/write/edit_file, list_directory.
6. Секреты: список «имя → значение», env_secrets и {{secret:ИМЯ}}, вырезание значений из вывода.
7. Мост от 403 (api.anthropic.com режет РФ): напрямую → sing-box 2080 → SSH-туннель через packetlab.
8. `on: user@host` — команды и файлы на packetlab/aeza. Без вкладок терминала, вывод в чате.
9. Автообновление.

Не делаем: сейф с паролем, синхронизацию, терминал, SFTP-менеджер, пробросы, мультиаккаунты.

## Архитектура (одинакова для C++ и Rust)

```
aicontrols.exe ──stdin/stdout (stream-json)── claude.exe (нативный CLI, ~\.local\bin)
   │  UI: окно чата, секреты                      │ HTTPS_PROXY=127.0.0.1:<порт>
   │  инструменты (MCP) ◄── control-протокол ─────┘
   │  подтверждения (can_use_tool)
   └─ локальный прокси-мост ──► напрямую / sing-box / SSH-туннель packetlab
```

- Без Node и без ACP-адаптера: `claude.exe -p --input-format stream-json --output-format stream-json`.
- Инструменты и подтверждения — по тому же каналу, как это делают официальные Agent SDK
  (`--permission-prompt-tool stdio`, MCP-сервер типа `sdk` через control_request `mcp_message`).
  **Проверить первым делом**: это внутренний протокол SDK, эталон — открытый claude-agent-sdk-python.
  Запасной путь (документированный): MCP по HTTP на loopback + `--mcp-config`, подтверждения — MCP-инструментом.
- Секреты: файл, зашифрованный DPAPI (CryptProtectData, привязка к учётке Windows). Без пароля.
- Переезд 8 секретов (GITHUB, CLAUDEFLARE, SERVER, CFTOKENAEZA, ROUTER, BRR, GROC, AEZA):
  скрипт из старого клиента через env_secrets → новый файл. Значения нигде не печатаются.

## Вариант A: C++23 (Win32 + Direct2D/DirectWrite) — ВЫБРАН

Плюсы:
- Всё уже есть из Sovereign: сборка (tools\sov-build*), MSVC /analyze, clang-tidy, фаззинг, CI,
  установщик, updater.cpp, WIL, nlohmann-json, ui_style.h, подход Painter. Не с нуля.
- Ноль внешних UI-зависимостей: Win32 и D2D не сломаются и не заставят переписывать через год.
  Это главный довод при условии «второй раз новый не делать».
- Поле ввода — системный RichEdit (msftedit): IME, отмена, вставка, проверка орфографии бесплатно.
- Exe ~2–4 МБ, память ~20–40 МБ, старт мгновенный.

Минусы / где работа:
- Лента чата рисуется самим: markdown → блоки → IDWriteTextLayout, выделение мышью через несколько
  сообщений, копирование, прокрутка с виртуализацией, стриминг без мерцания. Это самая крупная часть
  (оценка 2–3 тыс. строк).
- Подсветка кода: tree-sitter (C-библиотека) или простой токенайзер на 5–6 языков.
- SSH для `on` и туннеля: libssh2 через vcpkg. Прокси-мост: Winsock + IOCP/потоки.
- MCP/JSON-RPC без SDK — пишем сами, но там 4 метода (initialize, tools/list, tools/call, ping).

## Вариант B: Rust + gpui (движок Zed) + gpui-component

Плюсы:
- Готовые компоненты: markdown, подсветка, списки, ввод. Рабочий интерфейс получится быстрее.
- tokio, serde, russh (SSH), официальный MCP SDK `rmcp` — сетевая часть пишется очень легко.
- GPU-рендер 120 FPS, выглядит современно.

Минусы:
- gpui не обещает стабильный API вне Zed, документации мало, gpui-component тянется за git-версией
  Zed. Риск именно того, чего не хочется: через год обновление ломает всё и надо переписывать UI.
- Своего заводского конвейера нет: сборка, CI, установщик, обновления — заново (Velopack и т.п.).
- Rust не установлен (rustup + MSVC-тулчейн ~1 ГБ).
- Exe ~15 МБ.

## Отброшено

- Electron: тяжёлый, неинтересно.
- Tauri / WebView2: по сути тот же браузер внутри. Оставить только как аварийный вариант для ленты
  чата, если свой markdown в D2D превратится в болото (WebView2 есть в Windows 11, exe не растёт).
- Slint/egui: markdown и выделение текста слабые, выигрыша перед D2D нет.

## Этапы (для варианта A; для B такие же)

0. Разведка, 1 день: запустить claude.exe в stream-json из маленькой консольной программы,
   проверить control-протокол (инструмент + can_use_tool + resume). Если не взлетает — запасной путь.
1. Окно: лента сообщений (простой текст), RichEdit-ввод, стриминг, «Стоп», выбор модели.
2. Markdown + код + выделение/копирование. Самый долгий этап.
3. Инструменты + подтверждения + секреты (DPAPI) + переезд секретов.
4. Список чатов, resume, сообщение во время хода.
5. Прокси-мост от 403 (напрямую → sing-box → SSH packetlab).
6. `on` к серверам.
7. Установщик, автообновление, переезд; старый SSH Client удаляем только после недели на новом.

Старый клиент работает до конца переезда: разговор с Claude идёт через него.
